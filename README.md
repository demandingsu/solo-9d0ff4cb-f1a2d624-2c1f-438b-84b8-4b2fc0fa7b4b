# 环境监测小时观测数据平台

FastAPI + SQLite 的网页应用：测站结构（列名/列型）随时间演化，旧批次观测数据
仍可按**现役列名**统一查询，也可切回**历史版本**查看当时的列名与原始读数；
重传 / 补报批次按**批次优先级**归并，同一站号同一 UTC 小时只交付一行。

## 功能

- **发布初版结构**：自定义站号列、UTC 小时列与数据列（整数 / 小数 / 文本）。
- **按现役结构上传 CSV**：表头须与现役结构一致（顺序不限），逐行校验类型，
  任何一行不合格则**整批拒绝**，不产生半成品批次；可同时指定批次优先级。
- **结构演化（发布新版本）**，只允许三类安全变更：
  - 改列名（含站号/小时列，跨多版连续改名也能找回旧值）；
  - 新增**可空**列（旧批次该行显示空值）；
  - 整数列**扩型**为小数列（旧值原样保留，不做任何换算）。
- **拒绝并回滚**：删除旧列、两列合并、一列拆多列、缩型（小数→整数等）、
  改系统列类型、新增非空列、列名重复——全部拒绝，现役版本与供数不受影响。
- **统一查询**：按站号 + UTC 小时区间查询原始观测，所有批次用现役列名展示。
- **历史视角**：选择任一历史版本，只看该版批次，列名与读数都是当时的样子。
- **优先级归并（交付视图）**：以 `站号 + UTC 小时` 为键，**逐列**取优先级最高的
  非空值；同级同值只算一次（来源批次全部记录），同级异值标冲突、该小时不可交付；
  空值不遮盖更低优先级的有效读数。网页可查看每小时一行结果、各列来源批次与冲突原因，
  并下载 CSV；原始观测始终可在「原始观测」中回看。
- **调优先级只重算受影响小时**：修改某批次优先级后，只重算该批次涉及的
  `(站号, 小时)`，其他小时结果不变。
- **交错安全**：发布 / 上传 / 调优先级 / 查询均在全局锁 + 单事务内完成。
  上传或调优先级后，归并结果在**同一事务**内重算——失败整体回滚，
  不会出现批次已入库而归并为旧/半套结果的状态。

## 快速开始（Docker Compose）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

数据保存在命名卷 `obs-data` 中（容器内 `/srv/data/obs.db`）。

## 本地开发

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
# 打开 http://127.0.0.1:8000
```

## 页面操作流程（可用 examples/ 下的样例 CSV）

1. 「② 发布结构版本」发布初版：站号=`站号`，小时=`UTC小时`，数据列 `气温`(整数)、`气压`(整数)。
2. 「③ 上传」选择 `examples/v1_初版结构.csv`。
3. 「②」把 `气温` 改名为 `气温_C`、`站号` 改名为 `station_code`、`气压` 扩型为小数 → 发布 v2；上传 `examples/v2_改名扩型后.csv`。
4. 「②」把 `气温_C` 改名为 `温度`，新增可空列 `湿度`(整数) → 发布 v3；上传 `examples/v3_再加列后.csv`。
5. 「④ 归并结果」：每小时一行，列名随现役结构，单元格下方标出该列来源批次与优先级；
   有冲突的小时标红并列出各候选读数与原因，可用「下载 CSV」带走结果。
6. 「⑤ 原始观测」现役视角：v1 批次的 `温度` 列仍显示当年的 5/6/3，`湿度` 显示空值，`气压` 仍是整数 1013/1012/1015。
7. 再上传一份与 v1 同一小时、不同读数、优先级更高的 CSV（如 `S01,2026-11-18T00:00,7,`，
   优先级 5）：`温度` 取 7，`气压` 因高优先级为空仍取 v1 的 1013；
   若再用优先级 5 传 `8`，该小时变为冲突、不可交付。「⑥ 批次优先级」可调整后即时重算。
8. 「⑦ 版本历史」点 v1「以此视角查询」：只看到 v1 批次，列名是 `站号/气温/气压`，读数原样。

## API 一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/versions` | 全部版本（含列定义） |
| GET | `/api/versions/current` | 现役版本 |
| GET | `/api/versions/{no}` | 指定版本 |
| POST | `/api/versions` | 发布新版本（初版或演化），非法变更 400 |
| POST | `/api/batches` | 上传 CSV（multipart，字段 `file`，可选 `priority`），校验失败 400 且整批回滚 |
| GET | `/api/batches` | 批次列表（含优先级） |
| GET | `/api/batches/priorities` | 批次优先级列表 |
| POST | `/api/batches/{id}/priority` | 调整优先级 `{"priority": 5}`，只重算该批次涉及的小时 |
| POST | `/api/merge/recompute` | 全量重算归并结果（修复/排障用） |
| GET | `/api/merged` | 归并结果：`station`、`hour_from`、`hour_to`、`status`(ok/conflict)、`limit` |
| GET | `/api/merged.csv` | 下载归并结果 CSV（每小时一行，含来源批次 / 优先级 / 冲突原因） |
| GET | `/api/observations` | 原始观测：`station`、`hour_from`、`hour_to`、`version_no`（缺省=现役视角）、`limit` |

### 归并规则

- 键：`站号 + UTC 小时`；候选：所有批次中该小时的原始观测，按批次的 `priority`
  （整数，越大越优先）排序。
- 对每个数据列独立决策：忽略空值（`None` / 空白字符串），在剩余读数中取最高优先级；
  最高优先级内有多个来源时——读数相同只算一次（同时记录全部来源批次与文件名），
  读数不同则记冲突，`status=conflict`，该小时**整行不可交付**（不输出任一份读数）。
- 某列在所有来源中都没有非空值 → 该列输出空、来源为空。
- 冲突列的输出值留空，其余未冲突列仍显示各自归并结果，便于核查；
  交付状态列明确标“冲突·不可交付”，下游不会误用。
- 数值比较按数值（同一优先级下 `5` 与 `5.0` 视为同一读数）；文本按原文比较。
- 归并结果按 `(站号, 小时)` 存于 `merged_hours`，与原始观测同库同事务维护。

发布新版本请求体示例（演化）：

```json
{
  "note": "改名+扩型+加列",
  "columns": [
    {"source": "station", "name": "station_code"},
    {"source": "hour_utc", "name": "UTC小时"},
    {"source": "c1", "name": "温度"},
    {"source": "c2", "name": "气压", "type": "float"},
    {"source": null, "name": "湿度", "type": "integer", "nullable": true}
  ]
}
```

初版用 `{"role": "station"/"hour"/"data", "name": ..., "type": ...}` 声明列。

## 设计说明

- **列血缘**：每个逻辑列有稳定标识 `column_id`（`station` / `hour_utc` / `c1` / `c2` …）。
  改名、扩型复用同一 `column_id`，因此改名链跨多版仍可定位旧值。
- **原值存储**：观测值按上传时的解析结果存入 `observations.values_json`
  （`{column_id: value}`），之后任何版本操作都不改写它。新增列在旧行自然为空；
  扩型不回填（旧整数仍是整数，数值不变）。归并只读取它，从不改写原始观测。
- **事务与锁**：所有读写经 `db.session()`（全局 RLock + 单连接事务）。
  发布/上传/调优先级先完整校验再写入，并在**同一事务**内重算归并结果；
  失败整体回滚——失败操作后仍按原版本、原归并结果供数。
- **旧库升级**：启动时自动为 `batches` 补 `priority` 列（默认 0），
  若已有原始观测但没有归并结果则一次性回填；迁移与回填在同一事务内完成。
- **小时规范化**：`2026-11-18 03:00`、`2026-11-18T03:00:00Z` 等写法统一规范为
  `YYYY-MM-DDTHH:MM` 存储，区间查询按字典序比较（规范后等价于时间序）。

## 已知限制

- 单进程 + SQLite，适合单站/小团队部署；多实例水平扩展需换外部数据库。
- 历史视角只显示该版本上传的批次（“当时的列名与当时的读数”），不把新批次映射进旧结构；
  归并结果始终按**现役结构**展示（老批次按 `column_id` 映射，新增列显示空）。
- 冲突判定只在**最高优先级层**进行：若最高层读数一致，不会因为更低优先级有异值而报冲突
  （这正是优先级覆盖的含义）。
- 同一批次内若同一站号同一小时出现多行，按同一优先级处理：读数一致只算一次，
  不一致则视为冲突（不静默去重）。
- 归并结果保存在 `merged_hours`，只由上传 / 换版 / 调优先级 / 手动全量重算更新；
  直接改库不会自动反映，需调用 `/api/merge/recompute`。
- 同一最高优先级内出现多个来源时，只要读数一致就只取一份；来源批次列表按批次号升序展示。
- 小时列按整点/分钟对齐，秒级或非 ISO 写法会被拒绝。
